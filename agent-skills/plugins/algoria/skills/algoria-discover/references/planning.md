# Discuss the plan before execution

Apply this to every newly selected service or agent, not only media workflows.
After live discovery and any required balance check, explain in the user's
language: what you will do, which supplied references/data will be used, the
expected output, and the estimated total cost. Use the current catalog's
price and explicitly label the estimate; unknown provider costs stay unknown.
For an unpaid MCP call say there is no x402 charge, without claiming the
provider itself is free unless its terms establish that.

Let the user discuss or revise the plan before starting production. A fresh
creative task needs approval of the concrete plan, even if a spending cap
already exists. A previously approved plan and budget remain valid: do not
ask again on each stage, status check or recovery. For a straightforward
read-only request, a brief statement of the planned lookup and known cost
is enough; the user's request already authorizes that lookup.

For creative media, show the proposed scenes, exact narration, voice/language,
reference roles and output format in plain language. Do not make the user
write prompts, JSON or learn provider products. Do not assume they want to
appear in the output: a product-only request needs no person reference.

Once the plan is approved, prepare inputs and obtain the definitive quote.
Compare it with the estimate and remaining approved budget. Obtain missing
payment authorization, or renewed authorization if scope or cost exceeds
what was approved. Then execute and deliver the actual output. Funding a
wallet, discovering a service or reviewing a plan alone does not approve an
arbitrary payment. Never upload unrelated files or sign an uncertain retry.

Prefer a discovered composite service when it covers the complete approved
outcome. Use its single price and job; do not add its internal provider stages
as extra user purchases. Fall back to a chain only when the available service
cannot meet the request, and explain that plan and full cost first.
